# 유스케이스별 객체 관계

구현 클래스보다는 외부에서 사용하는 인터페이스와 도메인 모델을 표시합니다.
화살표에는 전달하는 요청을 한글로 쓰고, 실제 메서드 이름은 괄호 안에 표시합니다.

## Operation 내부 모듈

```mermaid
flowchart LR
    JOB["Job 관리<br/>(operation.job)"]
    TASK["Task 실행 관리<br/>(operation.task)"]
    WORKFLOW["실행 순서 조정<br/>(operation.workflow)"]
    SHARED["공용 외부 연동<br/>(operation.shared)"]

    WORKFLOW -->|"Job 상태 변경 요청"| JOB
    WORKFLOW -->|"다음 Task 생성 요청"| TASK
    TASK -->|"연결된 Job 실패 전달 (LinkedJobFailure)"| WORKFLOW
    JOB -->|"DB와 감사 기능 요청"| SHARED
    TASK -->|"Agent와 DB 기능 요청"| SHARED
    WORKFLOW -->|"DB와 인증 정보 요청"| SHARED
```

`Task → Workflow`는 구현 클래스에 직접 의존한다는 뜻이 아닙니다.

```text
TaskReportService · ExpiredTaskService
  → LinkedJobFailure 인터페이스 사용
  ← LinkedJobFailureService가 구현
```

Task 영역은 “연결된 Job을 실패 또는 시간 초과로 바꿔 달라”고 요청할 뿐입니다.
Job 조회, Lock과 상태 변경은 Workflow 영역이 담당합니다.

## 7. Task 성공 결과 보고와 후속 처리

```mermaid
flowchart LR
    AGENT[현장 Agent]
    REPORTS["Task 결과 보고<br/>(TaskReports)"]
    AGENTS["Agent 확인<br/>(AgentReader)"]
    STORE["Task 저장소<br/>(TaskStore)"]
    TASK["운영 Task<br/>(OperationTask)"]
    DISPATCHER["성공 처리기 선택<br/>(TaskSuccessDispatcher)"]
    HANDLER["Task 성공 처리 계약<br/>(TaskSuccessHandler)"]
    LINUX_HANDLER["Linux 상태 성공 처리<br/>(LinuxStatusTaskSuccessHandler)"]
    BACKUP_HANDLER["백업 성공 처리<br/>(BackupTaskSuccessHandler)"]
    HOST_STATUS["Agent Host 상태 기록<br/>(HostStatusWriter)"]
    BACKUP_RESULTS["백업 성공 결과 접수<br/>(BackupTaskResults)"]
    NEXT_TASK["Task 저장소<br/>(TaskStore)"]
    JOB["운영 Job<br/>(OperationJob)"]

    AGENT -->|"Task 성공 보고 (completeTask)"| REPORTS
    REPORTS -->|"Agent와 Token 확인 (findAgent, matchesToken)"| AGENTS
    REPORTS -->|"Task 조회 (findById)"| STORE
    REPORTS -->|"성공 결과 최초·중복 판정 (acceptSuccessReport)"| TASK
    REPORTS -->|"최초 성공 결과만 전달 (dispatch)"| DISPATCHER
    DISPATCHER -->|"Task 종류에 맞는 처리기 확인 (supports)"| HANDLER
    HANDLER -->|"Linux 상태 Task 구현"| LINUX_HANDLER
    HANDLER -->|"백업 Task 구현"| BACKUP_HANDLER
    DISPATCHER -->|"성공 결과 처리 요청 (handleSuccess)"| LINUX_HANDLER
    DISPATCHER -->|"성공 결과 처리 요청 (handleSuccess)"| BACKUP_HANDLER
    LINUX_HANDLER -->|"Linux 상태 기록 요청 (record)"| HOST_STATUS
    BACKUP_HANDLER -->|"성공한 Task ID 전달 (continueAfterSuccess)"| BACKUP_RESULTS
    BACKUP_RESULTS -->|"필요하면 복원 검증 Task 저장 (save)"| NEXT_TASK
    BACKUP_RESULTS -->|"백업 절차 종료 상태 반영 (succeed, fail)"| JOB
```

`TaskReports`는 성공 결과를 처음 받았는지만 판단합니다. 같은 결과 보고가 다시 오면
`TaskSuccessDispatcher`를 호출하지 않습니다.

`TaskSuccessHandler`는 Task 결과 접수 기능이 요구하는 출구입니다. 두 구현체는
`operation/task/adapter/integration`에 함께 있으므로 Task 결과와 관련된 객체를 한곳에서 찾을 수 있습니다.

```text
LinuxStatusTaskSuccessHandler
  → Agent Host 상태 기록

BackupTaskSuccessHandler
  → BackupTaskResults에 성공한 Task ID 전달
  → 복원 검증 Task 생성 또는 Job 종료
```

## 8. Task 실패 결과 보고

```mermaid
flowchart LR
    AGENT[현장 Agent]

    subgraph TASK_RESULT["Task 실패 접수"]
        REPORTS["Task 결과 보고<br/>(TaskReports)"]
        AGENTS["Agent 확인<br/>(AgentReader)"]
        STORE["Task 저장소<br/>(TaskStore)"]
        TASK["운영 Task<br/>(OperationTask)"]
    end

    subgraph JOB_RESULT["연결된 Job 반영"]
        JOB_FAILURE["Job 실패 전달<br/>(LinkedJobFailure)"]
        JOB_STORE["Job 저장소<br/>(JobStore)"]
        JOB["운영 Job<br/>(OperationJob)"]
    end

    AGENT -->|"Task 실패 보고 (failTask)"| REPORTS
    REPORTS -->|"Agent와 Token 확인 (findAgent, matchesToken)"| AGENTS
    REPORTS -->|"Task 조회 (findById)"| STORE
    REPORTS -->|"실패 결과 최초·중복 판정 (acceptFailureReport)"| TASK
    TASK -->|"최초 실패 판정 반환 (ACCEPTED)"| REPORTS
    REPORTS -->|"최초 실패만 전달 (fail)"| JOB_FAILURE
    JOB_FAILURE -->|"Job 잠금 조회 (findByIdForUpdate)"| JOB_STORE
    JOB_STORE -->|"연결된 Job 반환"| JOB_FAILURE
    JOB_FAILURE -->|"RUNNING이면 실패 상태 반영 (fail)"| JOB
```

`LinkedJobFailure`는 Task 영역의 required 인터페이스이고,
`LinkedJobFailureService`가 실제 Job 잠금과 상태 변경을 수행합니다. 독립 Task처럼
연결된 Job ID가 없으면 Task만 실패하고 이 흐름은 종료됩니다.

## 9. 만료된 Task 정리

```mermaid
flowchart LR
    TASK_SCHEDULER[Task 실행권 만료 검사기]
    EXPIRED_TASKS["만료 Task 정리<br/>(ExpiredTasks)"]
    TASK_STORE["Task 저장소<br/>(TaskStore)"]
    TASK["운영 Task<br/>(OperationTask)"]
    JOB_FAILURE["Job 시간 초과 전달<br/>(LinkedJobFailure)"]

    TASK_SCHEDULER -->|"만료 Task 정리 요청 (recoverExpiredTasks)"| EXPIRED_TASKS
    EXPIRED_TASKS -->|"만료 Task 잠금 조회 (findExpiredForUpdate)"| TASK_STORE
    EXPIRED_TASKS -->|"실행 횟수가 남은 Task 재대기 (requeueExpiredLease)"| TASK
    EXPIRED_TASKS -->|"실행 횟수를 소진한 Task 종료 (timeoutExpiredLease)"| TASK
    EXPIRED_TASKS -->|"최종 시간 초과만 전달 (timeout)"| JOB_FAILURE
```

실행 횟수가 남았다면 같은 Task를 다시 대기시킵니다. 마지막 실행까지 만료된 경우에만
`LinkedJobFailure`를 통해 연결된 Job도 시간 초과로 종료합니다.

## 10. 만료된 Job 정리

```mermaid
flowchart LR
    JOB_SCHEDULER[Job 실행권 만료 검사기]
    EXPIRED_JOBS["만료 Job 정리<br/>(ExpiredJobs)"]
    JOB_STORE["Job 저장소<br/>(JobStore)"]
    TASK_STORE["Task 저장소<br/>(TaskStore)"]
    EXPIRED_RULE["만료 후 행동 결정<br/>(ExpiredJobRule)"]
    JOB["운영 Job<br/>(OperationJob)"]

    JOB_SCHEDULER -->|"만료 Job 정리 요청 (recoverExpiredJobs)"| EXPIRED_JOBS
    EXPIRED_JOBS -->|"만료 Job 잠금 조회 (findExpiredForUpdate)"| JOB_STORE
    EXPIRED_JOBS -->|"연결된 Task 조회 (findByJob)"| TASK_STORE
    EXPIRED_JOBS -->|"Job과 Task 상태 전달 (decide)"| EXPIRED_RULE
    EXPIRED_RULE -->|"연장·재대기·실패·시간 초과 결정 반환"| EXPIRED_JOBS
    EXPIRED_JOBS -->|"결정된 상태 반영"| JOB
```

`ExpiredJobRule`은 상태를 직접 바꾸지 않고 필요한 행동만 결정합니다.
`ExpiredJobService`가 그 결정에 따라 Job 실행권을 연장하거나 Job을 재대기·실패·시간 초과로 변경합니다.
